## 2. CI/CD & Deployments

The backend uses a true GitOps pull model powered by GitHub Actions.

**Deploying Updates:**
1. Push code to the `main` branch.
2. GitHub Actions (`.github/workflows/deploy.yml`) will:
   - Build a new immutable Docker image.
   - Tag it with `sha-<git-commit-hash>` and push it to `ghcr.io`.
   - SSH into Oracle and modify `/opt/realitytunnel/current/.env` to point to the new image tag.
   - Run `docker compose config` (validation) and `docker compose pull`.
   - Run `docker compose up -d` to restart the service using the new image.

**Rollback Procedure:**
To roll back a bad deployment instantly without rebuilding:
1. SSH into the Oracle node.
2. Edit the `.env` file in `/opt/realitytunnel/current/` and change `DOCKER_IMAGE=` to the previous working `sha-XXXXX` tag.
3. Run `docker compose up -d --force-recreate billing-api`.

## 3. Database Restoration (PostgreSQL)

If the Postgres database crashes or becomes corrupted, the system uses automated daily dumps inside the `backup_data_prod` volume.

**To Restore:**
```bash
docker exec -i <postgres-container-name> psql -U billing -d billing_prod < /app/backups/latest_dump.sql
```

## 4. Key Management & Rotation

### JWT Key Rotation
JWTs are signed with Ed25519 asymmetric keys located on Oracle at `/opt/realitytunnel/secrets/jwt`.
If keys are compromised:
1. Delete the compromised keys: `rm -f /opt/realitytunnel/secrets/jwt/*.pem /opt/realitytunnel/secrets/jwt/*.pub`
2. Run the key generator: `python3 scripts/generate_signing_keys.py` (ensure you mount the new volume or run it locally and move the keys into place).
3. Restart the `billing-api` container.
*Note: This will instantly invalidate all existing user sessions.*

### Marzban Token Rotation
The Marzban connection relies on an Admin JWT generated by Marzban.
1. Access the Marzban panel or run `docker exec marzban-marzban-1 marzban-cli admin create ...`
2. Generate a new `sudo` access token.
3. Update `MARZBAN_API_TOKEN` in `/opt/realitytunnel/current/.env` on the Oracle server.
4. Restart the `billing-api` container.

## 5. External Integrations

- **Cloudflare DNS:** `144.24.153.180` should be proxied (Orange Cloud) for the API subdomains if Caddy is not handling raw TLS, or Unproxied (Grey Cloud) if Caddy expects to issue its own Let's Encrypt certificates directly.
- **Monitoring:** Node Exporter can be run on Oracle on port `9100`. Prometheus and Grafana should ideally be isolated on Contabo or a 3rd VPS to scrape Oracle over the `10.100.0.1` WireGuard interface.
